Attack chains (2)

1. Attack chain

  • Preconditions: Nginx is configured with 'underscores_in_headers on;'; Gunicorn is configured to pass request headers to the application; Nginx has a location block that denies access to '/admin/' paths; The application has a route '/admin/key' that returns the encryption key
  • Lateral moves: An attacker sends a request to '/asdf/admin/key' with a 'SCRIPT_NAME' header set to 'asdf/'; Gunicorn processes the 'SCRIPT_NAME' header and forwards the request to the application with the modified path '/admin/key'; Nginx's location block does not properly sanitize or validate the modified path, allowing the request to bypass the access control; The application returns the encryption key used to decrypt files
  • Impact: The attacker can obtain the encryption key, allowing them to decrypt sensitive files and potentially gain unauthorized access to restricted resources.
  • Remediation: Modify the Nginx configuration to disable processing of underscores in headers (set 'underscores_in_headers off;') and ensure proper validation of request paths before forwarding to Gunicorn. Additionally, review and secure Gunicorn's configuration to prevent unauthorized header injection and path manipulation.

2. Attack chain

  • Preconditions: 攻击者能够向目标服务器发送HTTP请求; 攻击者知道或猜出正确的key_id值; 服务器未对/admin/key端点进行适当的访问控制
  • Lateral moves: 攻击者发送GET请求到/admin/key端点，获取加密密钥; 攻击者利用获取到的密钥解密敏感文件（如flag.txt.enc）
  • Impact: 攻击者能够获取加密密钥并解密敏感数据，导致敏感信息泄露
  • Remediation: 在server/server.py中，对/admin/key端点添加身份验证机制，确保只有授权用户可以访问该端点。具体修改为在get_key函数中添加认证检查，例如在server.py的第55行添加以下代码： if not request.authorization or request.authorization.username != 'admin' or request.authorization.password != 'admin_password': abort(401, 'Unauthorized') 同时，建议在nginx配置中进一步限制对该端点的访问，例如在server/setup.sh中添加以下配置到nginx站点配置文件： location /admin/key { allow 127.0.0.1; deny all; }
