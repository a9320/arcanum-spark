Attack chains (2)

1. Attack chain

  • Preconditions: Nginx has underscores_in_headers enabled; Nginx proxy_pass_request_headers is enabled; Gunicorn is configured to read SCRIPT_NAME from headers; Flask application has /admin/key endpoint exposed
  • Lateral moves: Attackers send a request to /asdf/admin/key with SCRIPT_NAME header set to 'asdf/'; Nginx processes the request and strips the /asdf/ prefix based on SCRIPT_NAME; Nginx allows the request since it matches /admin/ but the location block is bypassed; Gunicorn uses the SCRIPT_NAME header to modify the PATH_INFO variable; Flask application processes the modified PATH_INFO and exposes the /admin/key endpoint
  • Impact: Attackers can bypass Nginx access controls and retrieve the encryption key via the /admin/key endpoint
  • Remediation: Modify Nginx configuration to disable underscores_in_headers and proxy_pass_request_headers, update Gunicorn to not read SCRIPT_NAME from headers, and remove the /admin/key endpoint from the Flask application

2. Attack chain

  • Preconditions: 攻击者能够发送HTTP请求到目标服务器
  • Lateral moves: 攻击者构造请求访问'/admin/key'端点; 获取加密密钥
  • Impact: 攻击者可以解密敏感数据，如flag.txt
  • Remediation: 修改server/server.py，添加权限验证到'/admin/key'端点，例如： server/server.py:55: @app.route('/admin/key') server/server.py:56: def get_key(): server/server.py:57: if not request.is_admin: server/server.py:58: abort(403) server/server.py:59: return jsonify(key=get_info()['key'])
