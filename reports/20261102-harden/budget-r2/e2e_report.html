server/setup.sh · AUTH_BYPASS

Attack path
Nginx 配置开启 underscores_in_headers 并 proxy_pass_request_headers on，请求头 SCRIPT_NAME 被透传至 gunicorn。gunicorn 会将 SCRIPT_NAME 头写入 WSGI environ，导致 Flask 路径被重写。攻击者请求 /asdf/admin/key 并发送 SCRIPT_NAME: asdf/，nginx 仅看到 /asdf... 放行，gunicorn 将实际 path_info 改为 /admin/key，从而绕过 location ^~ /admin/ { deny all; }。该漏洞可用于进一步访问未授权的密钥接口。

Attack chains (2)

1. Attack chain

  • Preconditions: Nginx配置中启用了underscores_in_headers; gunicorn启用了proxy_pass_request_headers; 攻击者能够构造包含SCRIPT_NAME头部的请求
  • Lateral moves: 攻击者构造请求路径/asdf/admin/key; 攻击者设置SCRIPT_NAME头部为asdf/; gunicorn将SCRIPT_NAME视为基路径，实际请求路径为/admin/key
  • Impact: 攻击者能够绕过Nginx的/admin路径访问限制，获取加密密钥并解密文件
  • Remediation: 修改Nginx配置文件，关闭underscores_in_headers功能，同时修改gunicorn配置，禁用从请求头读取SCRIPT_NAME头部。具体修改如下： 1. 在Nginx配置文件中，注释或删除underscores_in_headers on;（路径：server/setup.sh，行号：19） 2. 在gunicorn启动命令中添加--limit-request-line选项，限制请求行大小，防止头部注入（路径：server/entrypoint.sh，行号：6，修改为：setuidgid app gunicorn -w 8 server:app -b unix:/tmp/gunicorn.sock --user app --access-logfile - --limit-request-line 0）

2. Attack chain

  • Preconditions: The /admin/key endpoint is exposed without proper authorization checks.; The server allows unauthenticated access to the encryption key via this endpoint.
  • Lateral moves: An attacker sends a GET request to /admin/key to retrieve the encryption key.; The retrieved key is used to decrypt sensitive data, such as the flag file.
