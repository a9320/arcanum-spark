Attack path
nginx 配置开启 underscores_in_headers 并 proxy_pass_request_headers on，导致 SCRIPT_NAME 请求头被透传至 gunicorn。gunicorn 会将 SCRIPT_NAME 头写入 WSGI environ，导致 Flask 路径被重写。攻击者请求 /asdf/admin/key 并发送 SCRIPT_NAME: asdf/，nginx 仅看到 /asdf... 放行，gunicorn 将实际 path_info 改为 /admin/key，从而绕过 location ^~ /admin/ { deny all; }。

Attack chains (2)

1. Attack chain

  • Preconditions: nginx has underscores_in_headers enabled; gunicorn proxy_pass_request_headers is enabled; SCRIPT_NAME header injection is possible
  • Lateral moves: Attackers can send a request with SCRIPT_NAME header set to 'asdf/'; This modifies the request path to '/asdf/admin/key' which bypasses nginx's /admin/ deny rule; Access to '/admin/key' endpoint allows extraction of encryption key
  • Impact: Unrestricted access to encryption keys enables decryption of sensitive data including the flag
  • Remediation: Modify nginx configuration to disable underscores_in_headers and prevent SCRIPT_NAME header injection

2. Attack chain

  • Preconditions: 攻击者能够向服务器发送 HTTP 请求; 服务器配置允许访问 /admin/key 路径; 相关代码未被修改
  • Lateral moves: 攻击者构造 HTTP GET 请求访问 /admin/key 端点以获取加密密钥; 利用获取到的密钥解密加密的文件
  • Impact: 攻击者能够获取加密密钥并解密敏感数据，包括 flag.txt
  • Remediation: 修改 server.py 中的 get_key 函数，添加权限验证以确保只有授权用户才能访问该端点；在 Nginx 配置中进一步限制对 /admin 路径的访问
