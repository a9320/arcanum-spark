Attack chains (2)

1. Attack chain

  • Preconditions: Nginx has underscores_in_headers enabled; Nginx proxy_pass_request_headers is set to on; Gunicorn is configured to run as user 'app'; Gunicorn is set to read SCRIPT_NAME header
  • Lateral moves: Attackers send a request with a SCRIPT_NAME header to manipulate the request path; Attackers exploit the misconfigured Gunicorn to bypass Nginx's /admin/ restriction; Attackers access the /admin/key endpoint to retrieve the encryption key
  • Impact: Attackers can decrypt any encrypted files, including the flag.txt.enc file which contains the flag
  • Remediation: Modify the Gunicorn configuration in entrypoint.sh to disable reading the SCRIPT_NAME header or set it to a fixed value, ensuring that the header is not used to alter request paths

2. Attack chain

  • Preconditions: 攻击者能够向/admin/key发送请求; 服务器未对/admin/key访问进行身份验证
  • Lateral moves: 攻击者发送GET请求到/admin/key端点; 服务器返回加密密钥; 攻击者使用密钥解密敏感文件
  • Impact: 攻击者能够获取加密密钥并解密敏感文件，导致敏感信息泄露
  • Remediation: 在server.py中添加身份验证逻辑到get_key函数，确保只有授权用户才能访问该端点。具体修改如下：在server/server.py的第55-57行添加认证检查，例如检查用户是否有权限访问。例如，在get_key函数中添加@auth_required装饰器或在函数内部进行权限验证。
