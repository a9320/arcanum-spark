Conclusion

本审计发现高危的远程代码执行（RCE）漏洞。攻击者可以通过笔记接口（`app.py`）对 `title` 字段进行控制，利用缺乏过滤的缺陷实现对 Redis 缓存键的任意覆盖（缓存投毒）。结合 Flask-Caching 使用 pickle 进行序列化且仅反序列化以 `!` 开头的数据这一特性，攻击者可以注入恶意的 pickle 对象，从而实现远程代码执行。建议：1. 在 `app.py` 中对 `title` 输入进行严格过滤，禁止包含敏感缓存前缀；2. 将 Flask-Caching 的序列化机制从 pickle 更改为更安全的格式（如 JSON）。

Attack chains (2)

1. Attack chain

  • Preconditions: 攻击者能够构造并上传恶意的pickle对象; Redis缓存未对序列化数据进行充分验证
  • Lateral moves: 通过构造恶意的pickle对象覆盖Redis缓存键; 触发Flask-Caching的反序列化机制执行恶意代码
  • Impact: 攻击者能够执行任意系统命令，获取敏感文件内容（如flag.txt）
  • Remediation: 升级Flask-Caching到2.0.0及以上版本，并修改app.py中的缓存配置，设置CACHE_serializer='json'

2. Attack chain

  • Preconditions: 攻击者能够构造特定的标题以覆盖 Redis 键
  • Lateral moves: 攻击者可以构造恶意 pickle 对象并通过 Redis 缓存注入到 Flask 应用中; 攻击者可以利用 Flask-Caching 的缓存机制实现远程代码执行
  • Impact: 攻击者能够通过控制 Redis 键值对 Flask 应用进行任意代码执行，进而窃取敏感信息如 flag.txt
  • Remediation: 在 app.py 中对标题进行严格的过滤，避免包含 'flask_cache_view' 等特殊前缀；将 Redis 键限制在特定命名空间内，防止被覆盖
