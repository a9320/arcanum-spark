Attack chains (3)

1. Attack chain

  • Preconditions: 攻击者能够访问运行 Docker 的容器环境; Docker socket 挂载到容器内部; 容器运行在高权限模式下（如 root）
  • Lateral moves: 攻击者通过 Docker socket 创建一个新的容器，例如运行一个交互式 shell; 利用新容器的权限访问主机文件系统; 通过 Docker API 执行任意命令，例如安装恶意软件或窃取敏感数据
  • Impact: 攻击者可以完全控制主机系统，导致数据泄露、服务中断或其他恶意行为
  • Remediation: 移除 Docker socket 的挂载，限制容器的权限，例如使用非 root 用户运行容器，并配置 Docker 的安全策略以防止未授权的容器逃逸。具体操作包括修改 docker-compose.yml 文件，移除 /var/run/docker.sock 的挂载，并在 Docker daemon 配置中启用安全选项如 --icc=false 和 --iptables=true。

2. Attack chain

  • Preconditions: Nginx configuration has underscores_in_headers enabled; Nginx proxy_pass_request_headers is set to on; Gunicorn is configured to read SCRIPT_NAME from request headers; /admin/key endpoint exists in Flask application
  • Lateral moves: Attackers send a request to /asdf/admin/key with SCRIPT_NAME header set to asdf/; Flask application processes the request as /admin/key despite Nginx's /admin/ deny rule; Attackers retrieve the encryption key via the /admin/key endpoint
  • Impact: Attackers can bypass Nginx access controls to retrieve the encryption key and decrypt the flag.txt file
  • Remediation: Modify nginx.conf to disable underscores_in_headers and proxy_pass_request_headers, update gunicorn configuration to not read SCRIPT_NAME from headers

3. Attack chain

  • Preconditions: 攻击者能够向 /admin/key 发送 HTTP 请求; 目标服务器未限制 /admin 路径的访问控制; 攻击者能够解析返回的 JSON 数据以获取加密密钥

  • Impact: 攻击者能够获取用于加密的密钥，从而解密所有被加密的文件，包括敏感数据如旗帜文件
