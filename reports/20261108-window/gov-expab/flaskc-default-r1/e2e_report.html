Conclusion

本项目审计发现高危漏洞：通过 Redis 缓存投毒机制，攻击者可以实现远程代码执行（RCE）。 主要威胁： 1. **远程代码执行 (RCE)**：攻击者利用 Flask-Caching 库在读取以 `!` 开头的缓存值时会执行 Pickle 反序列化的特性，结合 Redis 键覆盖漏洞，可实现系统级命令执行。 2. **缓存投毒 (Cache Poisoning)**：由于笔记接口未对 `title` 参数进行过滤，攻击者可以恶意覆盖 Flask-Caching 的内部缓存键。 建议： - 在 `app.py` 中对用户输入的 `title` 进行严格的字符过滤，禁止包含 `flask_cache_view//` 等敏感前缀。 - 对存储到 Redis 的 `content` 进行校验，或者更换更安全的序列化方案（如 JSON），避免直接使用 `pickle` 反序列化。

1. Attack chain

  • Lateral moves: 攻击者构造恶意 pickle 对象并通过 Redis 存储到目标缓存键中; 攻击者触发 Flask-Caching 对缓存值的反序列化，执行恶意代码
  • Impact: 攻击者能够执行任意系统命令，从而完全控制服务器
  • Remediation: 在 app.py 中对 Redis 键值进行严格的输入验证和过滤，确保所有缓存值在存储和反序列化前经过安全检查
