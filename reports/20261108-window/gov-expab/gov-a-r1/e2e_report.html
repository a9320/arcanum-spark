Attack chains (3)

1. Attack chain

  • Preconditions: Docker socket mounted into container; Container runs as root
  • Lateral moves: Execute arbitrary Docker commands on host; Create new containers with malicious payloads; Escalate privileges to root on host system
  • Impact: Complete control over host system including file access, installation of malicious software, and potential compromise of all services running on the host
  • Remediation: Remove the Docker socket volume mount from docker-compose.yml and run containers with non-root privileges using user: - user: "app" in Docker compose file

2. Attack chain

  • Preconditions: underscores_in_headers enabled in nginx; proxy_pass_request_headers enabled in nginx; SCRIPT_NAME header handling in gunicorn
  • Lateral moves: Sending request to /asdf/admin/key with SCRIPT_NAME: asdf/; Bypassing nginx /admin/ deny rule; Accessing /admin/key endpoint to retrieve encryption key
  • Impact: Unrestricted access to sensitive decryption keys, allowing full decryption of encrypted files including the flag
  • Remediation: Modify nginx config to disable underscores_in_headers and set proxy_set_header SCRIPT_NAME ""; in server/setup.sh. Update gunicorn configuration to ignore SCRIPT_NAME header.

3. Attack chain

  • Preconditions: 攻击者能够发送 HTTP GET 请求到 /admin/key 端点; 攻击者能够控制SCRIPT_NAME请求头
  • Lateral moves: 攻击者获取加密密钥后可以解密加密的文件; 攻击者可以利用密钥解密其他受保护的文件
  • Impact: 攻击者能够绕过支付赎金的步骤直接获取加密密钥，进而解密敏感信息
  • Remediation: 修改server.py中的/app.route('/admin/key')路由，添加权限检查确保只有在支付赎金后才能访问密钥；修改Nginx配置限制SCRIPT_NAME请求头的传递；在Dockerfile中添加配置限制敏感请求头的传递
