Attack chains (3)

1. Attack chain

  • Preconditions: Attackers have access to execute Docker commands within the container
  • Lateral moves: Exploit Docker socket access to create a new container with host filesystem mounts; Mount sensitive directories like /root or /etc to extract contents; Escalate privileges by executing commands as root on the host system
  • Impact: Complete compromise of host system, allowing arbitrary code execution and data extraction
  • Remediation: Modify docker-compose.yml to remove the docker.sock volume mount and set user: app in the service definition

2. Attack chain

  • Preconditions: 攻击者能构造并发送自定义HTTP头的请求; 目标服务器配置了underscores_in_headers和proxy_pass_request_headers; 目标服务器运行了gunicorn和Nginx; Flask应用暴露了/admin/key接口
  • Lateral moves: 攻击者构造请求路径为/asdf/admin/key，并设置SCRIPT_NAME头部为asdf/; 利用gunicorn解析SCRIPT_NAME头部功能，将实际请求路径改写为/admin/key; 绕过Nginx的location ^~ /admin/ deny all规则，成功访问/admin/key端点; 获取加密密钥后解密flag.txt.enc文件
  • Impact: 攻击者能够绕过访问控制，获取加密密钥并解密敏感文件，导致机密信息泄露
  • Remediation: 在Nginx配置中禁用SCRIPT_NAME头部传递，或在gunicorn中限制允许的头部；修改Flask应用代码增加路径检查，确保请求路径未被篡改；定期进行安全审计和配置检查

3. Attack chain

  • Preconditions: 攻击者能够访问目标服务器; 服务器正在运行且未被封禁
  • Lateral moves: 攻击者向 /admin/key 发送请求，获取加密密钥; 利用获取到的密钥解密受保护的文件（如 flag.txt.enc）; 进一步尝试利用密钥访问其他受限资源
  • Impact: 攻击者能够绕过支付赎金的步骤，直接获取加密密钥并解密敏感文件，导致数据泄露和潜在的经济损失。
  • Remediation: 修改 server/server.py 文件，确保在访问 /admin/key 时检查 paid 标志，只有在已支付赎金的情况下才返回密钥。具体修复代码如下： server/server.py 行 52-54，添加对 paid 标志的检查，返回 403 错误当 paid 为 false。
